---
title: "Environment"
description: "The environment variables Demoman reads."
---

| Variable | |
| --- | --- |
| `DEMOMAN_HOME` | Where Demoman keeps its videos, sessions and settings; `~/.demoman` by default |
| `DEMOMAN_DISPLAY` | The screen to record at, as `<width>x<height>@<scale>` (such as `1710x1107@2`), when Demoman cannot read the display, as on a machine with no screen. Demoman says when to set it. Its scale is also the one headless records motion at, ahead of any other; without it, a flow records at its latest video's scale, and a new one at 2, or 3 for a phone |
| `DEMOMAN_NO_UPDATE_CHECK=1` | Turns off the once-a-day check for a newer version |
| `DEMOMAN_HELD_CLOCK=0` | Records in real time, as every video was recorded before held capture became the default. By default a headless run records on a clock Demoman holds, one frame of the page's own time at a time, so one script gives the same timing on any machine outside the time spent waiting on the server. The video follows the server only while the script is waiting on the page (a page load, the settle after a step, a `waitFor`); a `pause` and the rests between steps are never the server's time, and an answer still arriving during one lands where the machine puts it, which the run report says. Outside the server's time: the same frames between steps, and a step that follows a server wait within a few frames of where it was. Every frame and still is at the scale the video is recorded at, so a full-quality export of a video recorded on a held clock is at most 1440p, where one recorded in real time reaches 4K. The page's `requestAnimationFrame` callbacks run once per recorded frame. A smooth scroll the page asks for shows as a jump, and the run report says so. What arrives over a websocket or an `EventSource` is not paced by the server, so it lands where the machine puts it. A visible window and a device's video always record in real time; the run report's `run.recording` says which clock a video was recorded on, and why. **Known issue:** a `<video>` playing on the page can stand still on one frame for a few seconds of the video, often with no note in the report; set this to record such a page in real time. A page whose script waits in a loop on `performance.now()` or `Date.now()` stops a run on a held clock after 15 s, and the run report says to set this |
| `DEMOMAN_SECRET_<NAME>` | A demo account's secret ([accounts.json](/reference/accounts-json#secrets)) |
| `DEMOMAN_SECRET_<NAME>_ORIGIN` | The one site that secret may be typed on |
| `DEMOMAN_NOW` | Set by Demoman, not you: the pinned instant, given to the app's commands ([app.json](/reference/app-json#pinned-dates)) |
| `DEMOMAN_DEFAULT_BRANCH` | Set by the workflow `setup --ci` writes for a deployment or release: the default branch it checked the commit is on. `refresh --deliver pr` opens its pull request into it; without it, `gh` says which branch |

<Note>
  An agent may pass Demoman only part of its environment, as Codex does, so
  a variable exported in your shell may never reach it. Set it where your
  agent starts Demoman, or keep secrets in `.demoman/secrets.env`.
</Note>
